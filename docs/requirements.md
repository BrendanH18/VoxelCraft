# VoxelCraft requirement inventory

[← Roadmap](roadmap.md) · [Documentation index](README.md) · [Verification records](verification/)

This is the M0 per-requirement inventory: the roadmap's
[core requirement groups](roadmap.md#4-core-requirement-catalogue) split into
individual rows. Each row has a state, the release that owns it in the
[release plan](roadmap.md#release-plan), its evidence and its acceptance cases.
It was written on 2026-10-15 against `t3/roadmap-next-stage-v0-8` after
`c152eb0`. The reference is Java Edition 26.3.

**Refreshed 2026-11-09** against `main` at `c96240b`: each row's state,
release, evidence and gaps were compared with the verification records up to
the [v0.16 integration](verification/2026-11-07-v0.16-integration.md), with
spot checks in `src/`. No row became Verified. A row still Partial or Missing
after its release was implemented or tagged was marked `unassigned`; the
[2026-11-09 audit](verification/2026-11-09-project-audit.md) then gave each of
those 26 rows the release that owns what remains
([roadmap](roadmap.md#content-assigned-by-the-2026-11-09-audit)).

**Rules.** The states are those of [§2](roadmap.md#2-status-and-tracking-rules).
A row is **Verified** only when every acceptance case passes for a recorded
commit: correctness against the reference, the owner's ordinary play (controller and CLI paths through their automated
adapter tests where they apply), save/reload,
and the M5 performance gate where the feature costs frame or tick time. The
[2026-10-16 M5 baseline](verification/2026-10-16-m5-baseline.md) is the
reference for that gate; it fails in streaming, so only PERF-01 is Verified
so far. Update a row in the
same change as the code or evidence it describes. Add rows when a group
turns out to contain more; never merge rows to hide a missing member.

**Columns.**

- *Release*: the version that should close the row.
  v0.8 was declared done on 2026-10-20 with its rows unverified: they moved to
  v0.9 for the player acceptance pass, and PERF-03 to v0.20. v0.9 was declared
  done on 2026-10-22: the owner's play is the player evidence for the v0.8 and
  v0.9 rows, and their remaining M5 performance check moved with them to v0.20.
  v0.10 (updates) and v0.11 (menus and settings) were inserted on
  2026-10-22 and the later releases renumbered, so building materials is
  v0.12.
- *Evidence*: the latest record or source.
- *Acceptance*: what must pass, beyond the automated checks that already do.
  "Player" means the owner's own ordinary play (owner, 2026-10-22); there is
  no formal checklist or physical-controller session.
- *Gaps*: known differences from Java and the next action.

Shared acceptance for every row: player acceptance and save/reload (P/S),
and an M5 scene that reaches the gate (M5) where the feature has a runtime
cost.
