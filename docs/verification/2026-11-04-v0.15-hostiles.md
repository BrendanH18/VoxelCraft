## Delivered behavior

- `Stray`, `Bogged`, `Phantom` append after `Camel`, using Java entity ids as
  their saved/summon names. Original procedural models/face noise; bogged
  mushrooms disappear after shearing, including on LAN replicas.
- Strays: 20 health, skeleton dimensions and goals, daylight burning; snowy
  plains/ice spikes skeleton weight 20 / stray 80, packs of four, with the
  additional sky-visibility check above powder snow. Snowy taiga/beach and
  frozen ocean retain skeleton weight 100 in the pinned 26.3 data.
- Skeleton conversion has separate exposure and countdown clocks, saved with
  identity, equipment and health retained. Java starts the countdown at 140
  exposure ticks, then converts after the countdown becomes negative (301
  countdown steps). **Leaving powder snow cancels conversion**, resets exposure
  to -1, and therefore takes 141 exposure steps on re-entry. These details
  follow 26.3 `ConversionTracker`, rather than assuming a 440-step total.
- Bogged: 16 health, swamp/mangrove swamp skeleton weight 70 / bogged 30,
  groups of four; poison arrows and slower ranged interval. Shearing once
  rolls two equally weighted independent brown/red mushroom entries, with
  one durability use through the shared hand interaction.
- Bones/ordinary arrows use skeleton loot pools. Player kills additionally
  roll 0–1 tipped arrow, with Looting's rounded increase capped at one:
  Slowness for strays, Poison for bogged. `mob_drops` gates all these drops.
- Mob-fired arrows are unpickupable and have custom Slowness I (600 ticks) or
  Poison I (100 ticks). Loot arrows carry the registered potion and use
  `max(1, floor(duration / 8))`. Potion components distinguish stacks, survive
  inventories and charged-crossbow save/reload, and remain on pickup.
- Shared bows/crossbows accept tipped ammunition, prioritize the offhand,
  consume tipped arrows even with Infinity, and retain effects on Multishot
  and Piercing shots. Main-hand bow drawing and all existing adapters remain
  shared. LAN snapshots carry potion identity and phantom size.
- Bow spawn enchantment chance is `0.25 * special_multiplier`; its provider
  uses non-treasure options with inclusive cost 5 through
  `5 + floor(17 * special_multiplier)`. Bow components persist through saves
  and skeleton conversion. Player-kill equipment drops use 8.5% + 1%/Looting
  and the Java nested-random wear formula. Non-chain armor items also drop;
  remaining armor limitations are below.
- Phantoms: 20 health, base 0.9 × 0.5 dimensions, size 0–64, scale
  `1 + .15 * size`, attack `6 + size`, undead effects, daylight burning,
  circle/anchor and swoop phases, collision/hurt/cat retreat and flying move
  control. The natural size is zero. Anchor and size save with each mob.
- `spawn_phantoms` defaults true, is saved/settable as `doInsomnia` too, and
  freezes the spawner countdown when off. Attempts are every 60–119 seconds,
  at sky darkening >=5, for non-spectators at/above sea level with visible
  sky, passing the local-difficulty roll. The actual rest predicate is
  **`nextInt(clamp(time_since_rest, 1, i32::MAX)) >= 72000`**, so the first
  possible rest value is 72,001. Groups are 1 through difficulty id + 1;
  positions are bottom-centred cells, ±10 horizontally and 20–34 above.
  Like the reference custom spawner, this bypasses the ordinary monster cap.
- Rest is a per-player tick statistic, saved for the host and named player
  profiles (including controller/LAN players); old saves default to zero.
  Accepted bed sleep resets it, sleeping does not accumulate it, and death
  resets it. Paused/offline time does not advance it.
- Phantom membranes drop 0–1 on player kills, plus Looting, and brew awkward
  potions into Slow Falling; redstone uses the existing long-potion recipe.
  **Membrane item 1020 already existed** and is retained, not reallocated.
- The End fight already contains dragon-owned breath clouds. Glass bottles
  now collect from clouds intersecting the player's box inflated by two,
  reducing cloud radius by .5 (clamped at zero), through shared use. This
  supplies a survival source for the new dragon-breath item.
- Splash potion + dragon breath brews the same potion in a lingering bottle;
  modifiers preserve its component. Brewing returns the glass bottle (stacked
  ingredients spill the remainder through the world's drop path). A 3×3 grid
  of eight arrows around that lingering potion crafts eight matching tips.
- Lingering projectiles create clouds at block impact / struck entity feet:
  radius 3, wait 10 ticks, duration 600, shrink -.005/tick and -.5 per affected
  recipient, five-tick probes and 20-tick reapplication delay; ordinary effects
  last one quarter, instant effects are half strength. Immune recipients do
  not consume radius. Clouds save/reload with cooldowns, unload with chunks,
  replicate to LAN and render original deterministic translucent motes.

  Additive player field: `time_since_rest`; cloud property: `potion_clouds`.

## Differences and remaining verification

- New variants reuse existing skeleton navigation, target selection, ranged
  positioning, projectile ballistics, damage and daylight exposure. Variant
  shot spacing uses Java's minimum interval + 20-tick draw: stray 60/40,
  bogged 90/70 ticks (non-Hard/Hard). First-shot windup and sight-loss handling
  are still the simplified skeleton implementation, not the full goal.
- Local difficulty uses the existing clock/moon calculation with inhabited
  chunk time zero. This affects spawn and equipment probabilities relative to
  a long-inhabited Java chunk. Exact shared RNG sequence parity is not claimed.
- Armor spawn/glint chances use the existing Java routine. Actual armor
  enchantments remain visual glint flags; chainmail has no item representation
  and cannot drop. Armor attributes/enchantment protection are not a completed
  Java equipment simulation. Bow components are actual enchantments.
- Phantom goal selection/scanning and cat retreat are integrated directly at
  20 Hz, rather than the full Java GoalSelector scheduling framework. The
  move control uses the reference turning/speed/velocity equations, but the
  existing collision engine supplies movement; water/ground travel friction,
  cat-search cadence and transient anchor/retarget details need parity work.
  Distinct variant/phantom voices, conversion shaking and swoop sounds are
  absent; original synthesized skeleton calls are reused.
- Cloud recipients are processed players then mobs, rather than Java's single
  living-entity query order; crowded clouds can consume radius in a different
  order. Clouds and stack contents persist, while in-flight/embedded arrows
  and thrown potions inherit the existing projectile disk-save gap.
- Player hit/status effects use existing separate event sinks; shield or
  invulnerability rejection is not atomically shared with tipped-effect
  application. Other potion-engine limitations (water extinguishing, complete
  brewing catalogue and every Java status interaction) remain PRO-02 work.
  Arrow icons are generic purple tips, with names/projectile potion colors.
- No Terra graphical run or screenshot inspection has been performed in this
  Sol child. The project assigns computer-use gameplay to Terra; this brief
  prohibits further delegation. The reproducible scene below is prepared for
  the integrator. Owner play, full restart/old-world acceptance and active
  mob/cloud performance remain unverified; no feature is marked Verified.
