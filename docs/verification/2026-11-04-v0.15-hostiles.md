# v0.15 track 4 — hostiles and tipped arrows

Status: **Partial; implemented, unverified**. This is a tested-slice handoff,
not a claim that MOB-04b or PRO-02 is complete. No owner play evidence.

## Delivered

- Append `stray` and `bogged` after `Camel`; Java entity names are the save and
  summon keys. Existing biome tables now resolve both entries to real mobs:
  snowy plains and ice spikes have skeleton 20 / stray 80, packs of four;
  swamp and mangrove swamp have skeleton 70 / bogged 30, packs of four.
  Strays additionally require sky visibility, scanning above powder snow.
- Stray health 20, bogged health 16; skeleton dimensions 0.6 × 1.99,
  undead effect immunity, sunlight burning, skeleton/wolf-avoidance goals,
  original frost-cloth and moss/mushroom geometry with procedural face noise.
  Bogged mushrooms disappear after shearing, including on LAN replicas.
- Skeleton conversion tracks exposure separately from the conversion countdown.
  Java 26.3 starts at 140 exposure ticks and converts when the subsequent
  300-tick countdown becomes negative (301 countdown steps). Leaving powder
  snow resets exposure to -1 and cancels conversion, matching ConversionTracker.
  Identity, health, equipment, effects and persistence survive conversion.
- Bogged shearing uses two independent, equally weighted brown/red mushroom
  rolls, once only, through the shared hand interaction (including wear).
- Bones and ordinary arrows use the existing skeleton loot pools. Player kills
  additionally roll 0–1 tipped arrow, with Looting's rounded uniform increase
  capped at one, containing Slowness or Poison respectively. Mob loot gates it.
- Mob arrows remain unpickupable and apply custom Slowness I for 600 ticks or
  Poison I for 100 ticks. Player tipped arrows carry any registered `Potion`
  and apply each registered effect at `max(1, floor(duration / 8))`.
- Tipped ammunition works through the shared player bow/crossbow implementation,
  including Infinity consumption (only ordinary arrows are infinite), Multishot,
  Piercing, offhand ammunition priority and charged-crossbow save/reload. Pickup retains potion data for the
  host/controllers and CLI agents. LAN arrows include potion identity.
- Natural strays/bogged and skeleton conversion clocks are included in the
  existing mob save path; shearing and potion payloads survive reload.

## IDs and formats

- Item **1330**: `tipped arrow` (Java `tipped_arrow`). No block states or
  reserved block texture layers consumed. Models use original procedural
  vertex colours/noise; the arrow icon follows the existing item-icon atlas.
- MobKinds appended in order: `Stray`, `Bogged`. Integrator must order all
  tracks' appended kinds before shipping the LAN roster.
- Existing stack component `entity_data`: on tipped arrows, `Potion` index + 1;
  on charged crossbows, the same for their bolt, zero for an ordinary bolt,
  `u32::MAX` for an empty tipped bolt. The existing text stack serializer and
  equality checks already preserve and distinguish this payload. Existing
  drinking/splash potion item IDs are unchanged.
- New optional mob JSON `freezing` holds exposure, countdown and fractional
  ticks. Older saves without it use the ordinary constructor defaults.

## Differences and remaining work

- **Phantoms are not implemented**: no insomnia statistic, PhantomSpawner,
  circle/swoop flight, phantom size, membrane, Slow Falling brewing recipe,
  or `spawn_phantoms` enforcement. Its game-rule row remains Missing.
- **Lingering potions, area-effect clouds and tipped-arrow crafting are not
  implemented.** The repository has no dragon's-breath item or collection
  action (dragon breath exists as fight damage). No substitute brewing recipe
  was invented. Survival tipped arrows are obtainable from stray/bogged loot;
  other registered potion payloads currently need programmatic stack creation.
- Variants reuse VoxelCraft's existing skeleton movement, target selection,
  line of sight, aiming spread, arrow damage/ballistics and sun exposure.
  These are not a full Java RangedBowAttackGoal port. New variant shot spacing
  uses Java's minimum interval plus the 20-tick draw: stray 60/40 ticks,
  bogged 90/70 ticks (non-Hard/Hard); first-shot windup and sight-loss handling
  remain the existing simplified skeleton behavior. Ordinary skeleton timing
  is unchanged.
- Armor spawn rolls use the existing local-difficulty routine (inhabited time
  is still zero). Bow/equipment enchantment chances and equipment drops remain
  the pre-existing skeleton gap. No claim of equipment parity is made.
- Mob-fired arrow effects on mobs enter through the current mob-hit event path;
  player hit/effect events likewise use the existing separate damage/effect
  sinks. Shield/invulnerability rejection is not yet atomically shared with
  tipped-effect application. Instant effects inherit existing magic damage
  model. Exact RNG sequence parity is not established.
- Conversion sound/shaking and distinct variant voices are absent (original
  synthesized skeleton voice is reused). Arrow icons use a generic purple tip;
  projectile tips and names reflect registered potion contents. In-flight and
  embedded arrows inherit the existing no-disk-save projectile limitation.
- **No scripted game screenshot or visual inspection was run in this Sol
  implementation role.** Project instructions require Terra for running and
  looking at game scenes; this child brief prohibits further delegation.
  Terra visual evidence, ordinary play, full persistence restart and performance
  with large active mob populations remain for integration.

After copying this worktree's built binary, a Terra agent can capture both
variants on an isolated elevated platform with this reproducible scene:

```sh
python3 - <<'SCENE'
import pathlib, subprocess
out = pathlib.Path("target/v015-hostiles-scene")
out.mkdir(parents=True, exist_ok=True)
args = ["/tmp/v015-hostiles-vc", "--data-dir", str(out),
        "--new", "--world", "hostiles", "--seed", "42", "--creative",
        "--rd", "2", "--time", "0.75", "--pose", "0,150,0,0,0",
        "--spawn", "stray,6,150,-2", "--spawn", "bogged,6,150,2",
        "--wait", "0.2", "--screenshot", str(out / "hostiles.png")]
for x in range(3, 10):
    for z in range(-4, 5):
        args += ["--place", f"{x},149,{z},stone"]
subprocess.run(args, check=True)
SCENE
```
