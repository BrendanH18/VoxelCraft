## Delivered

- `MobKind::Allay`, `allay` command/save identity, LAN index **70**. Legacy
  indices unchanged, 69 reserved for the concurrent creaking track. No
  block states or item IDs. Item range 1380–1384 and texture range
  3424–3439 remain unused/reserved. Skin/wings use original cuboid colours
  and the existing per-texel noise shader; held stacks use existing art.
- Shared `PlayerSession::use_held` gifting, empty-hand return, shard
  duplication callback. Survival consumes one gift/shard; Creative retains
  it. Every actor records its own PlayerId; controller/agent/LAN adapters
  use this shared action. Name tags/leads retain existing interaction priority.
- Liking follows `Allay.allayConsidersItemEqual`: same item and equal
  `potion_contents` (tipped arrows and lingering potions compare their
  potion in `entity_data`; other potions are distinct item IDs), every other
  component ignored. The single slot then follows `SimpleContainer.canAddItem`
  (empty, or same item and components below the maximum). The first
  implementation was stricter (all components); corrected 2026-11-05.
- Pickup uses a per-tick item bucket index and local queries. Delayed items
  cannot be collected (including the existing 40-tick player-thrown delay),
  cargo never exceeds its stack maximum, all components survive partial
  pickup, return, delivery, death and storage. `mob_griefing` gates pickup.
- Liked player following, retrieval, one-item throws, 60-tick pickup lock;
  note target overrides player. Gameplay note queue is independent of audio
  draining. Vibration delay, wool occlusion, note refresh/expiry/removal and
  fallback are implemented. State pauses in inactive chunks.
- Two distinct persistent resident markers in the existing generation-3
  cage. Structure population/save keys prevent duplicates and resurrection.
  Generation 1/2 legacy outposts do not receive allays; block painting and
  existing positional RNG streams are unchanged.
- Liked/cargo stacks, liked player, note position/timer, pickup and duplication
  timers, dance/jukebox state, healing phase and pending vibration save.
  Replicated appearance carries the allay payload and held item. Newborn
  duplication state copies neither owner nor inventory. Death drains owned
  stacks once; held Vanishing equipment is suppressed; no ordinary loot/XP.
- Original animated cyan model with wings, face and held item; original
  synthesized bell-like ambient, hurt/death and interaction sounds.

## Differences and gaps

- **Jukeboxes and music discs are absent** (only the audio category exists).
  There is no existing “playing jukebox” state to connect. The saved dance
  state, playback callback, animation and shared amethyst duplication logic
  are implemented/tested as integration hooks. Survival dancing/duplication
  remains unavailable. Do not count the callback tests as survival evidence.
- Woodland mansions do not exist, so mansion allays remain unavailable.
- AI uses the existing bounded flying navigator and compact sensor/memory
  state rather than a full Java Brain scheduler. Idle fly/look probabilities,
  exact path/RNG sequences and unreachable-path behavior are not identical.
  The give behavior uses the 20-tick run/start cadence, but scheduler ordering
  and sensor initial random phase are not reproduced. Generic panic memory
  is shared with existing mobs. Render orientation uses the engine's yaw
  convention; turn/pitch limits and flying travel constants are ported.
- Notes use six bounded voxel rays between cell centers with the Java face
  offsets and tie order. Event selection coalesces nearest notes in one simulation interval and does
  not reproduce all chunk-ready/event-order rules of VibrationSystem. Note
  queue/callback wiring uses `update_world`, the desktop authoritative path;
  direct `Entities::update` callers must dispatch note events separately.
- Existing original outpost cage geometry stays as delivered in v0.14, not
  replaced with Mojang structure art/layout. Integer resident markers at
  (4,1,4)/(4,2,4) approximate native fractional positions and provide unique
  persistence keys. Residents retain the native template's initial 10 health and .3 ground-speed
  override; flying speed remains .1 and regeneration restores them to 20.
- Liked-player targeting uses the shared player context: Adventure is not
  distinguished from Survival there, and non-standing eye positions use a
  box-height estimate. Those lookup/pose details remain parity gaps.
- Taking the liked item back drops the carried stack at the allay
  (`drop_from_block`) rather than Java's `BehaviorUtils.throwItem` from its
  position; the player receives the liked item as in Java.
- The original model's wings spread sideways from the back; seen from the
  side they are edge-on and nearly invisible (Java's wing planes extend
  backward). The held item sits in the hands at chest height.
- Liked-player melee, player arrows and instant harming damage are rejected.
  Rejected arrows currently disappear instead of Java's refusal bounce.
  Other shared-engine environmental/effect damage categories retain their
  existing implementation. Player identity is the engine's saved PlayerId,
  not a Java UUID. No allay advancement criteria are implemented.
- Original art/sounds differ from Java assets. Ambient with/without-item
  calls share the synthesized voice; throw pitch choices are not ported.
  Ordinary player interaction, rendering and performance acceptance remain
  unverified until the evidence below and owner play are complete.
