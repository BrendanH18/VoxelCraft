Status: **Implemented, unverified.** No owner play is claimed, and no agent

Claude Opus 5.5 as the Track C1 implementation agent of the v0.17

from `registry_gaps.json`.

## What was built

- **Block** (`src/world/crafter.rs`): Java's 48 states, twelve
  `FrontAndTop` orientations × `triggered` × `crafting`, at states
  13088–13135; the item is the default state (`north_up`, idle). A full,
  opaque, conducting cube with per-face layers that follow the
  orientation (front, back, top, bottom, two sides) and light up while
  triggered or crafting. Hardness 1.5, blast resistance 3.5, mined faster
  with a pickaxe and dropping itself without one; the recipe; the creative
  palette; original art in layers 1200–1210.
- **Placement** (`CrafterBlock.getStateForPlacement`): the front faces the
  player (the nearest looking direction's opposite); facing down, the top
  points opposite the player's horizontal facing; facing up, along it;
  otherwise up. `triggered` is `hasNeighborSignal` at the cell, and a
  crafter that starts triggered schedules its craft (`setPlacedBy`).
- **Slots**: the nine slots are the crafter's chest-table entry, as a
  dispenser's are, so saving, spilling on break, hoppers, droppers, LAN
  container sync, piston immovability and the CLI's `chest take/put` all
  reach them. The block entity (`world::crafter::Crafter`) keeps the
  disabled slots and `craftingTicksRemaining`, saved in the new `crafters`
  dimension property with Java's `disabled_slots` and
  `crafting_ticks_remaining` keys. A slot turns off or on only while empty
  (`CrafterBlockEntity.setSlotState`, which the server's packet handler
  calls); nothing goes into a disabled slot (`CrafterSlot.mayPlace`).
- **Filling** (`canPlaceItem`): hoppers and droppers put an item into the
  first enabled slot that isn't full and is either empty or holds a stack
  no smaller than any later enabled slot's stack of the same item (an
  empty later slot also refuses it), which spreads items smallest stack
  first. `world::crafter::slots_for_face` and `World::crafter_can_place`
  are the seam Track C2's sided transfers use: the crafter isn't a
  `WorldlyContainer`, so every face reaches all nine slots.
- **Crafting** (`neighborChanged`, `tick`, `dispenseFrom`,
  `dispenseItem`, `serverTick`): a rising edge sets `triggered` and
  schedules a craft 4 game ticks later; a falling edge clears `triggered`
  and `crafting`. The craft runs the game's recipe matcher
  (`crafting::Grid::result_in`, with the world's maps) on the grid. With
  no result it plays the failure sound. With one it turns `crafting` on
  for 6 block-entity ticks (counted down only for crafters whose countdown
  runs, after the scheduled ticks, as Java's block entities tick after
  them), post-processes the result (`onCraftedBySystem`: a zoomed-out
  map's id), then ejects the result and each remainder in grid order
  (`Grid::remainders`, the recipe's `getRemainingItems`: buckets,
  bottles, bowls, a copied book or banner) out of the front: into the
  container there (one item at a time into another crafter), and what's
  left as a dropped item through the dropper's spawn (speed 6, 0.7 out)
  with the craft sound and white smoke. Every filled slot then loses one.
- **Comparator** (`getRedstoneSignal`): the number of slots that are
  filled or disabled.
- **Sound and particles**: `Sound::Crafter(Craft | Fail)`, original
  procedural stand-ins (`src/audio/crafter.rs`) played as `BLOCKS` at
  volume 1, pitch 1; the smoke is a world particle request, so LAN guests
  get both through the existing sound tap and effect sync.
- **Screen** (`src/app/crafter.rs`, `hud.rs`, `screen.rs`): the crafter
  opens the chest screen with `CrafterMenu`'s layout (grid at 26,17, the
  result at 134,35): disabled slots are covered, an arrow with a redstone
  indicator shows `triggered`, and the result slot previews what the grid
  makes. Clicking an empty enabled slot with an empty cursor turns it off
  (with the click sound); clicking a disabled slot turns it on and then
  takes the click, so a held stack goes in. Hovering an empty enabled slot
  says "Click to disable slot". Shift-click skips disabled slots. The
  controller menu shows the same covers, indicator and preview, and its A
  button runs the same click. LAN guests get the disabled mask with the
  chest snapshot (`crafter_disabled`) and click through the host's screen
  transaction.
- **CLI agents**: `crafter toggle 0..8` on an aimed crafter, `chest put`
  refused for a disabled slot, and `observe` lists a targeted crafter's
  slots, disabled slots, `triggered`, `crafting` and preview.

## Tests

`tests/crafter.rs` (15 tests): the fixture's constants, states,
orientations, strength, drops, tags and sounds against the game; the
recipe through `Grid`; every placement case against the fixture's `top`
rule; the special-recipe table against the fixture (and the repair gap);

crafters doing no saved work. `world::crafter` has unit tests for state
round trips, placement and the art. The existing block loot, mining,
registry-gap and recipe audits pass with the crafter registered.

## Differences from Java

- Neighbour notifications are drained at the start of the next redstone
  tick (the engine's existing queue; Track A owns Java's update order), so
  a crafter sees a rising edge one game tick after Java would; the four
  ticks from `triggered` to the craft match.
- The `setPlacedBy` craft is scheduled whenever a block edit creates a
  triggered crafter (player placement, `setblock`), not only for a placing
  entity.
- `triggered` is the block state; the block entity doesn't save Java's
  separate `triggered` key (Java sets both together, and from the state
  when the block entity is created).
- Ejection reaches block containers only. Java's
  `HopperBlockEntity.getContainerAt` also finds container minecarts in
  front; VoxelCraft's droppers don't do that either.
- The `RecipeCache` (ten entries) isn't modelled; each craft matches the
  nine-slot grid directly.
- The `crafter_recipe_crafted` advancement trigger isn't implemented.
- Client-only parts aren't in the server jar and were written from
  knowledge of the client, unverified: the white smoke (ten particles out
  of the front), the toggle click (volume 0.4, pitch 1 on, 0.75 off), the
  "Click to disable slot" hint and the screen art. Sounds and textures are
  original; face textures aren't rotated with the orientation.
- Java's number-key swap onto a disabled slot (which turns it on) has no
  counterpart: VoxelCraft's screens have no number-key swaps.
- Item repair and sherd decorated pots (see the table) are matcher gaps
  shared with the crafting table.
