# v0.12 registry audit — 2026-10-23

[Roadmap](../roadmap.md#v012-scope-building-materials) · [Requirement inventory](../requirements.md) · [ID reservations](../architecture.md#release-id-reservations-v09v019)

Scope: planning evidence for v0.12 (building materials, closing M2), on
`e5050f6`. It compares VoxelCraft's registered block and item names with
Java 26.3's and sorts every missing block into the release where its source
or dependency arrives. It is a name-level inventory; it checks no states,
behaviour, recipes or acquisition, and it marks nothing Implemented.

## Reference

Minecraft Java Edition **26.3**, official client
`client.jar`, SHA-1 `e877b6a07acd633fb3bb475002175cec036e7b87` (matches
the launcher's 26.3 version metadata). Every block has a blockstate file and
every item an item-model file under `assets/minecraft/`, so their file names
are the registry names; display names come from `lang/en_us.json`. Item
frames and glow item frames have blockstate files but are entities, so the
extractor leaves them out of the block list.

```sh
python3 tools/extract_java_registry_names.py /path/to/client.jar \
  --output tests/fixtures/java/26.3/registry_names.json
cargo run --release --no-default-features --example registry_audit > target/registry-audit.json
```

`registry_audit` resolves each Java name, then its display name. Blocks
resolve only through `Block::from_name` (or, for beds, which register each
half, the bed item), so an item of the same name doesn't hide a missing
block: the wither skeleton skull is an item but can't be placed. Items
resolve through either registry. It also lists VoxelCraft names that match
no Java name. A name that resolves can still lack states or behaviour (for
example, overworld logs resolve but store no axis).

## Results

| Measure | Count |
|---|---|
| Java 26.3 blocks | 1,286 |
| Java 26.3 items (including block items) | 1,658 |
| Java blocks with no VoxelCraft name | 669 (11 of them are only named differently) |
| Java items with no VoxelCraft name | 833 (block items of missing blocks included) |

The release plan's v0.12 row named a few families (pale oak, bamboo, mud
brick, prismarine). The audit shows M2 is much larger. Pale oak and bamboo
already have stairs, slabs, fences, gates, doors, trapdoors, buttons and
pressure plates, and mud brick and the prismarines have stairs and slabs; the
gaps are elsewhere:

- **Wood:** no stripped overworld logs or wood, no `*_wood` blocks, and no
  buttons, pressure plates or trapdoors for spruce, birch, jungle, acacia,
  dark oak, mangrove or cherry. No signs, hanging signs or shelves for any
  wood. Overworld logs have one state each, so they can't be placed
  sideways (crimson and warped stems, basalt and hay already store an axis).
- **Stone:** no polished tuff or tuff bricks, deepslate bricks or tiles,
  quartz, smooth, cut and red sandstone, red nether bricks or end stone
  bricks, and no mossy stone brick, sandstone, brick or nether brick shapes.
- **Copper:** only the ore, raw block and plain block exist. All 113
  oxidised, waxed, cut, chiseled, grate, bulb, door, trapdoor, bars, chain,
  lantern, chest, torch and lightning-rod blocks are missing.
- **Colour:** no banners, candles or candle cakes, and none of 26.3's 64
  wool and concrete stairs and slabs.
- **Utilities:** no cauldrons, campfires, flower pots or potted plants, coral
  wall fans, trapped or ender chests, decorated pots, lodestones or respawn
  anchors; and no item frames, paintings or armor stands among the items.

26.3 also has content that is new since the roadmap was written: the poplar
wood family with its coloured leaves, cinnabar and sulfur stone families
(with sulfur springs and the sulfur cube), shelves for every wood, wool and
concrete stairs and slabs, cushions (an entity placed from an item), the
straw bed, copper golem statues, and the red shrub and golden dandelion.

### Blocks VoxelCraft registers that Java lacks

Eleven registered building blocks have no Java 26.3 counterpart, contrary to
BLD-01 ("don't invent counterparts Java lacks"): calcite stairs, slab and
wall; deepslate stairs, slab and wall (Java shapes cobbled and polished
deepslate, not plain deepslate); smooth stone stairs and wall (Java has only
the slab); and polished granite, diorite and andesite walls.

The other unmatched names are internal states or display differences
(bed halves, flowing fluids, plant tops, `lit furnace`, `wool` for white
wool, `chain` for `iron_chain`, `grass` for `grass_block`), and the item
side lists potions and goat horns, which VoxelCraft names by their contents.

## State-ID budget

Counting only blockstate files that list their variants, the five v0.12
groups need at least **4,268** states (wood 1,076, copper 940, colour
1,586, stone 554, utilities 112), before waterlogged partners and the 32
multipart blocks (shelves, walls, bars). The real total with VoxelCraft's
one-ID-per-Java-state layout is likely 7,000–10,000. v0.12 has 2,595 IDs
reserved (2525–4095 and 8704–9727), and the unassigned reserve adds 2,048.
v0.12 therefore needs a `STATE_CAPACITY` raise (BLD-06). Block items are
`BLOCK_ITEM_BASE` (0x8000) + state, so the current item encoding allows at
most **32,768** states.

## Not checked

States, shapes, recipes, drops, fuel, compost, survival acquisition and
behaviour of any block; the 833 missing items beyond the block items above;
Java's full state count. Item frames, paintings and armor stands are
entities and are listed from the item side only.
