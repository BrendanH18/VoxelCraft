## Follow-up fixes (2026-11-06, takeover)

GPT-6.1 Sol stopped at a usage limit with the track nearly complete; Claude
Opus 5.5 merged `t3/ocean-ruins-archaeology` (eb5f85e) and finished it:

- **Emerging reward.** `render::brushable` draws the resolved reward of a
  partly brushed block as Java 26.3's client `BrushableBlockRenderer` places
  it (javap of the client jar): centre `0.5 + translations(face, dusted)`
  with `f = dusted / 10 * 0.75` (east/south `0.73 + f`, west/north
  `0.25 - f`, up `0.25 + f`, down `-0.23 - f`), half-block size, turned 86°
  (176° on the east-west axis) and lit from the brushed face's neighbour.
  It uses the shared item sprites and block models (shelf-item path) and
  shows nothing at dust 0, before the first stroke or for an empty reward.
- **Stroke effects.** Each stroke (ticks 5, 15, ...) dusts the brushed face
  with nine block particles (Java `nextInt(7, 12)`), on every input path,
  and replicates to LAN clients through the shared particle requests.
  Completion adds the suspicious block's destroy particles (level event
  3008). Desktop, controller and LAN hands play a light scrape of the
  block's material per stroke and its break sound on completion. This fixes
  the earlier stroke sound: it went through the mining-hit timer, which only
  advanced by one frame per stroke, so most strokes were silent.
- **Chunk-load cost.** Registering suspicious blocks on chunk load now
  returns at once for byte chunks and for palettes without these IDs, as
  `register_beehives` does, instead of walking all 32,768 cells of every
  loaded chunk.
- **Scripted scenes.** `--brush x,y,z,face,strokes` brushes a suspicious
  block (adding its ocean-ruin table if it has none) and holds the dust
  stage for the capture.

## Remaining differences and evidence limits

- Original VoxelCraft designs are explicitly requested, but they do not
  establish Java's template-layout fidelity. No owner fidelity exception is
  inferred. The cold overlay geometry shares the original masonry motif;
  the primary template supplies sediment.
- Chest seeds still use the engine's deterministic positional stream rather
  than Java's decoration-time post-processing stream. Structure selection
  is represented by choosing the variant matching the biome in the shared
  grid, rather than replaying Java's weighted attempt ordering. Full Java
  world-seed coordinate/content parity remains unverified.
- Biome membership is sampled from the engine surface column; Java's
  height-dependent biome-coordinate parity remains unverified. Drowned
  markers reuse the existing resident machinery; Java structure-spawn
  equipment and population gating were not independently re-audited.
- Brush sounds are the nearest original shared sounds (a light scrape of
  the block's material, then its break), not dedicated
  `item.brush.brushing.*` sounds. CLI agents' strokes make dust particles
  but no sound. The brush has no dedicated held-item sweep animation; the
  hand swings each stroke. Extracted drops use the engine's integer-cell
  drop queue rather than Java's exact fractional item-entity origin.
- LAN clients see dust stages and particles, but not the emerging reward:
  brushable block-entity data (reward and face) isn't replicated.
- The shared block ray does not include Java BrushItem's intervening-entity
  ray check. Other interaction-range and block-use priority rules are shared.
- Falling uses the existing engine's continuous gravity/drag approximation;
  its two-tick start and no-placement/no-drop outcome match BrushableBlock.
- This save format also preserves brush progress/deadlines; Java only saves
  loot/item and hit direction, and resets brush progress on block-entity load.
  Reloaded deadlines use the saved global simulation clock.
- The general warm-ocean-ruin explorer-map item from abandoned camps is still
  absent with that existing structure/map gap. Treasure maps **inside** ruin
  chests use the existing implemented buried-treasure map path.
- Trail-ruin/desert-well/desert-pyramid archaeological loot and processors
  remain deferred under narrowed DEF-02; existing ordinary sediment stays.
- No owner's ordinary play, GPU/frame-time acceptance, exact Java world
  comparison or LAN visual block-entity payload acceptance is claimed.
