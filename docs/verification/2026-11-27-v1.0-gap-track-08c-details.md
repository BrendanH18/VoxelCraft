## Scope

What [Track 8b](2026-11-27-v1.0-gap-track-08b-details.md#remaining-differences)
left in portal and projectile code:

1. End portals and End gateways through Java's `PortalProcessor` timing and
   cooldown; what Java builds before refusing a trip with
   `allow_entering_nether_using_portals` off; the sign editor (and any
   other screen Java closes) closing in a portal.
2. Fire drawn on burning arrows and tridents, as Java's client draws an
   entity on fire.
3. Mobs that refuse an arrow bouncing it back as Java's do, and a player's
   End crystal blast and its death message.

All three are done for arrows and tridents. What remains, including three
questions for the owner, is [listed below](#remaining-differences).

## What changed

### End portals and gateways count through `PortalProcessor` (item 1, GEN-04c)

`world::portal::PortalProcessor` now carries Java's portal (`PortalKind`:
Nether, End or gateway) and entry cell. `enter` is `setAsInsidePortal`
off cooldown: another kind of portal starts a new count
(`isSamePortal`), and a count already marked this tick keeps its first
entry cell.

- **End portals.** Touching one marks the player inside it; the next
  tick's `handlePortal` (at the start of the tick, before the player moves)
  takes them through, the `Portal` default delay of 0 making it the next
  tick rather than the tick of touching. The trip sets Java's 10-tick
  cooldown, which runs down only once the player has arrived (it doesn't
  count down while the destination loads, as `ServerPlayer` skips it while
  changing dimension), and touching an End portal on cooldown restarts the
  cooldown instead (`setAsInsidePortal`). In the End, a player who hasn't
  seen the credits still gets them in the tick they touch it, as
  `EndPortalBlock.entityInside` shows them at once.
- **End gateways.** A gateway that isn't cooling down starts its cooldown
  and beam as the player touches it and marks them inside, and the next
  tick's `handlePortal` takes them to its exit (nothing if the gateway has
  gone by then). Before, the trip began in the tick of touching.
- A Nether count running when the player touches an End portal or gateway
  is replaced by the new portal's, as in Java.

### What a refused Nether trip still builds (item 1, GEN-04c)

`NetherPortalBlock.getPortalDestination` runs before
`teleportToPortalDestination` checks `isAllowedToEnterPortal`, so with
`allow_entering_nether_using_portals` off Java still searches the Nether
for an exit portal and, finding none within 16 blocks, builds one with
`createPortal`, and only then refuses the trip. VoxelCraft now does the
same, deferred: a refused trip records an owed portal (the trip's scaled,
border-clamped target and the entry portal's axis, as `travel` computes
them), saved in the root level file (`owed_nether_portals`). The next time
the Nether loads, before the arrival, each owed portal in turn waits for
its ground to stream in behind the arrival screen, then gets
`getExitPortal`'s search and, finding nothing, `createPortal`.

This gives the Nether the portal Java would have built: the refusal can
only happen in the Overworld, the Nether doesn't change while the player
isn't in it, and the search and the builder are the ones a trip uses, so
the same search over the same unchanged Nether builds the same portal.
Identical owed portals are kept once and at most 256 are kept. A
spectator's refused trip owes none (`getExitPortal` builds spectators
nothing), and a LAN client's is the host's. **For the owner:** this is a
deferred build rather than loading the Nether in the background at the
moment of the refusal; say if you want the latter.

### Screens Java closes in a Nether portal (item 1, GEN-04c)

`handlePortalTransitionEffect` closes every screen whose
`isAllowedInPortal` is false, which is `isPauseScreen` unless overridden.
Besides containers and the inventory (Track 8b), that is the sign editor
and a lectern's book (`LecternScreen`); a book in hand, the pause menu,
chat, the death screen and the credits stay. The menu toolkit's screens
now say whether they are allowed in a portal (`Screen::allowed_in_portal`,
true by default), and `Game::portal_effect` closes one that isn't as
Escape would: the sign editor keeps its text, as Java's `removed()` sends
it. End portals and gateways close nothing (`Transition.NONE`). In an
unshared world every menu screen pauses the game, so this shows only in a
shared one (LAN host, agents).

### Burning arrows and tridents drawn on fire (item 2, PRO-05)

`entity::model::flame` is Java's `FlameFeatureRenderer`: square quads
facing the camera about the vertical axis only, scaled by 1.4 times the
box's width, each 0.45 higher, 0.9 times as wide and 0.03 further back
than the last, the stack pushed 0.3 toward the camera, textures alternating
`fire_0` and `fire_1` (mirrored from the third quad on), in block light 15
and the entity's sky light, cut out of the block atlas. A burning arrow or
trident (0.5 by 0.5 boxes: two quads, 0.98 blocks tall) now draws it,
Flame arrows included, in flight and stuck. VoxelCraft has one fire texture
(seven frames at ten a second, as the fire block draws it); the `fire_1`
quads take it three frames on.

In Java every projectile that applies block effects can catch fire and is
then drawn burning; here only arrows and tridents carry fire
([below](#remaining-differences)).

### Mobs that refuse an arrow bounce it back (item 3, PRO-05)

In 26.3 a living target refuses an `AbstractArrow` (an arrow or a
trident) when its `hurtServer` returns false. For the mobs here that is: a
Wither charging up, a powered Wither (at half health), a shut shulker, a
warden digging or emerging, a skeleton horse trap's horsemen while their
`setInvulnerableTime(60)` lasts, a scared armadillo against a hit of 1 or
less, and a lit sulfur cube; the dragon, breezes and decorations were
already handled. For each:

- **Arrows** now bounce back (`deflect(REVERSE, .., 0.2)`, a tenth of the
  speed, turned 170 to 190°, from outside the mob's box), dropping as an
  item if left almost still. The fire a burning arrow would have lit is put
  back, and nothing else happens: no damage, knockback, potion, kill credit
  or event. Before, the arrow was taken away. The powered Wither's refusal
  is now read with the arrow's damage type (it was read with none, though
  the damage itself was refused).
- **Tridents** already bounced off them with their hit sound, as Java's
  do; unchanged.
- **Endermen** refuse every projectile (unless riding) and teleport, and
  `projectileReceivesSideEffectsOnHit` is false for them, so nothing
  bounces: an arrow flies on, as before, and a burning one now sets the
  enderman alight (`igniteForSeconds(5)` comes before the hurt and is
  never undone); a trident now flies on too, with no hit sound, where it
  used to bounce back off them.

VoxelCraft's mobs have no hurt cooldown, so the commonest refusal in Java
(a second hit within half a second no harder than the first) can't happen
here ([below](#remaining-differences)).

### A player's End crystal blast (item 3, PRO-05)

`EndCrystal.hurtServer` blows up as `explosion(crystal, player)` when a
player is behind the blow (their hit, arrow, trident or other
projectile), a `player_explosion` whose message is
`death.attack.explosion.player`: "was blown up by a player" here (the
game names players "a player" in every death message). It was the
`explosion` type with "was blown up by an End crystal". A crystal with
nobody behind it blows up with no source entity but itself, which Java's
`death.attack.explosion` words "blew up", naming no one: that is now its
message too. A mob behind the blow is named as Track 8b made it. Block
breaking and drops are unchanged (the crystal's blast is a block
interaction either way).

### Scripted projectiles for captures

`--projectile arrow|trident,x,y,z[,fire]` sticks an arrow or trident in
the top of a block for a scripted scene, burning if asked; these never
despawn, as software captures take minutes. The capture scenes
`burning-projectiles` and `unlit-projectiles` use it.

## Remaining differences

Questions for the owner:

- **Mobs' hurt cooldown.** Java's `LivingEntity.hurtServer` refuses a hit
  no harder than the last one within ten ticks of it (`damageCooldownTime`,
  `lastHurt`), and arrows bounce off a mob refusing them that way.
  VoxelCraft's mobs have no hurt cooldown for any damage: adding it changes
  every source of mob damage (melee, blasts, fire, the rest), which is mob
  combat rather than projectile work. Not done here.
- **Fire on other projectiles.** In Java snowballs, eggs, ender pearls,
  thrown potions, bottles o' enchanting, fireballs, Wither skulls, wind
  charges, shulker bullets, firework rockets and fishing hooks all apply
  block effects, so fire and lava set them alight; they are then drawn
  burning, and a burning one lights a campfire, primes TNT or lights a
  candle it hits. Here only arrows and tridents carry fire. Giving the rest
  fire is gameplay beyond drawing; not done here.
- **Mobs and players drawn burning.** Burning mobs still draw the old
  rising cubes (mob model code, Track 7d's area) and a burning player isn't
  drawn on fire in third person or by other players at all; Java draws
  them with this same flame. `entity::model::flame` is ready for both.

Smaller differences:

- **Creative players** refuse arrows in Java (`isInvulnerableTo`), which
  bounce off them; here arrows pass through them, as through spectators.
- **One fire texture:** Java's flame alternates `fire_0` and `fire_1`; the
  game has only one fire texture, so the second quad shows it three frames
  on.
- **Death messages** name players "a player", not their name, and don't
  have Java's `.item` form for a custom-named weapon.
- **Unowned TNT** still says "was blown up by TNT" where Java's
  `explosion(tnt, null)` says "blew up"; mobs hurt by a mob-blamed blast
  don't turn on that mob; primed TNT from a burning projectile names no
  igniter (from Track 8b).
- **A lectern** pauses an unshared world here, as every menu screen does,
  where Java's `LecternScreen` doesn't pause; the same holds for the sign
  editor.
- Track 8b's other remaining differences (fire found along the box's
  sweep at quarter-block samples) and Track 8's stay as recorded there.
