## What was built

### Fixtures from the jars

`tools/extract_java_creative_fixtures.py` (Python 3.9, Ruff-clean) writes
three fixtures from the pinned server (`33680f5f…`) and client
(`e877b6a0…`) jars:

- `tests/fixtures/java/26.3/creative_tabs.json`: it compiles and runs
  `tools/JavaCreativeTabs.java`, an original JDK oracle, against the
  server jar. The oracle bootstraps the registries and calls Java's own
  `CreativeModeTabs.tryRebuildTabContents(FeatureFlags.DEFAULT_FLAGS,
  permissions, lookup)` without and with operator permissions, then lists
  every tab in registry order (row, column, type, alignment, title key,
  icon, scroll and title flags) with its display stacks and the stacks it
  gives the search tab, each as an item id and its component patch. The
  client receives data-driven registries sorted by id (the server reads
  them from the data pack's file listing), so the oracle lists
  enchantments, painting variants, instruments and banner patterns in id
  order and binds the jar's tags in file order. The extractor checks that
  the search tab is the other tabs' search stacks in order, each once, and
  records only its count (2000 stacks without permissions, 2034 with).
- `tests/fixtures/java/26.3/creative_layout.json`: `javap` of
  `CreativeModeInventoryScreen` and its `ItemPickerMenu`, `InventoryScreen`,
  `AbstractContainerScreen`, `HotbarManager` and `Options`. Each method's
  numeric literals are checked against an expected sequence (the extractor
  fails if Java changes) and recorded: the 195 x 136 panel, the 9 x 5 grid
  at (9, 18) and hotbar at (9, 112), the scrollbar (175, 18, 14 x 112, a
  12 x 15 thumb travelling 95, dragging centred 7.5 down the thumb), the
  26 x 32 tabs (27 apart; right-aligned ones at `195 - 27 x (7 - column) +
  1`; hit boxes at -32 and 136, drawn at -28 and 132, hover box 3, 3, 21 x
  27; icon centred and nudged a pixel toward the panel), the title at
  (8, 6) in #404040, the search box (82, 6, 80 x 9, 50 characters), the
  Survival Inventory tab's slots (armour at (54 + 54 col, 6 + 27 row),
  off-hand (35, 20), main grid (9, 54), Destroy Item (173, 112)) and its
  player preview ((73, 6)-(105, 49), 20 pixels a block), the survival
  inventory's preview ((26, 8)-(75, 78), 30), the follow-the-pointer
  formula (`atan(d / 40) x 20` degrees), nine saved hotbars in
  `hotbar.nbt`, the Save and Load Hotbar Activator keys (C and X: 26.3's
  key defaults are USB HID usage ids, 6 and 27), the English labels, and
  the centred panel at every supported GUI scale of 1920 x 1080 and
  1280 x 720.
- `tests/fixtures/java/26.3/spawn_eggs.json`: every `SpawnEggItem` with its
  entity type, category, `isAllowedInPeaceful`, stack size, English name,
  whether a tab lists it, the class `EntityTypes`' factory builds (from
  `javap -v` of `EntityTypes`' bootstrap methods; `EntityType.getBaseClass`
  is a stub), and what `spawnOffspringFromSpawnEgg` does with that class:
  `breed` for an `AgeableMob` whose nearest `getBreedOffspring` isn't just
  `return null` (36 eggs), `set_baby` for another mob overriding `setBaby`
  (7: the zombie family, piglin, zoglin), `none` (45). 26.3 gives each egg
  its own texture rather than Java's old tinted pair, so the two colours
  are numbers taken from the jar's texture: the means of a two-cluster
  split of its interior pixels (the outline left out), larger first.
  VoxelCraft draws its own egg with them.

### Creative tabs (`src/creative.rs`, library)

The game reads `creative_tabs.json` itself (embedded, parsed once on first
use) and resolves each entry to a stack: the item by its Java id
(`java_registry::item`), then its components: potion contents (drinkable,
splash and lingering potions, tipped arrows), stored enchantments,
firework flight, ominous bottle amplifier, suspicious stew effects and the
ominous banner. Entries whose item the game doesn't register are skipped
(each one is a `registry_gaps.json` entry). Painting variants and goat
horn instruments collapse to their single item, listed once. Thirteen tabs
show without operator permissions, in Java's order; Operator Utilities is
empty and hidden, as Java hides it without the Operator Items Tab option
and permissions.

`creative::scroll` is `ItemPickerMenu`'s arithmetic (rows past the five
shown, `(int)(offs x rows + 0.5)`, wheel steps of one row's share,
dragging, the thumb). `creative::click` and `clone` are
`slotClicked`'s rules for a creative cell: a click takes one (Shift a full
stack); on the same stack left adds one (Shift fills it) and right takes
one off; on another stack or an empty cell left deletes the held stack and
right takes one off; a middle click puts a full stack on an empty cursor.
`creative::Hotbars` is `HotbarManager`: nine rows of nine, stored per
install in `saves/hotbars.txt` beside `options.txt` (Java's `hotbar.nbt`),
one line of `stack_to_string` fields per row.

### The creative screen (`src/app/creative.rs`)

Java's layout from the layout fixture, drawn as flat rectangles in the
game's panel style: unselected tabs behind the panel, the selected one
joined to it, each with its icon; titles on hover. Building Blocks is the
first tab, and the choice is kept between openings as Java keeps
`selectedTab`. The wheel and the scrollbar (press and drag) scroll; the
thumb greys out when nothing scrolls. Search Items shows a focused search
box and filters as you type (every word in the name or enchantment lines);
the chat key (T) on any other tab jumps to it; a number key over a filled
cell swaps instead of typing; Escape closes. Saved Hotbars shows the nine
saved rows, with a locked paper placeholder ("Save hotbar with C + n") in
an empty row's own column. Survival Inventory shows armour, off-hand,
inventory and hotbar at Java's positions, Destroy Item (a click deletes
the held stack; Shift-click empties the whole inventory, crafting grid
included) and the player preview. In item tabs Shift-clicking a hotbar
slot deletes its stack (`quickMoveStack`). Number keys over a cell put a
full stack in that hotbar slot, Q throws one (Ctrl+Q a stack) and a middle
click clones. Active effects show to the panel's left. In play, C + 1–9
saves the hotbar (with Java's message) and X + 1–9 loads it, in creative
only; both keys rebind under Controls → Key Binds → Creative Mode.

### Survival inventory and player preview

The survival inventory now uses `InventoryScreen`'s positions: armour down
the left (8, 8 + 18i), the default player in (26, 8)-(75, 78), the
off-hand at (77, 62), the 2 x 2 grid at (98, 18), the result at (154, 28)
and the main grid at y 84, with "Crafting" at (97, 8) as Java labels it.
`src/app/preview.rs` draws the default player from VoxelCraft's own skin
(`player_model::skin_pixels`) as one flat quad per base-layer texel, an
orthographic view sorted back to front: the body turns by
`atan((centre x - pointer x) / 40) x 20` degrees, the head as much again
and pitches by the vertical one, and the figure tilts by it, as
`extractEntityInInventoryFollowsMouse` does.

### Spawn eggs

`src/content/spawn_egg.rs`: 87 items, 1850–1936, in the fixture's order
(the Spawn Eggs tab's, then the Wither's, which no tab lists), named as
Java names them, stacking to 64, creative-only (no recipe, loot or trade).
Each icon is original: an upright egg in the base colour with spots of the
second. `src/entity/spawn_egg.rs` and the use chain (`session::interact`):

- **On a block** (`SpawnEggItem.useOn`): into the clicked cell when its
  collision shape is empty (grass, flowers), else in front of the clicked
  face; the mob is put a block higher and dropped onto the collision
  shapes in that cell, at most a block (two, reaching the cell below, when
  the egg went on a top face): `EntityType.getYOffset`. It stands at the
  cell's centre, `entity_place` is posted, the mob's ambient sound plays
  (`playAmbientSound`), and survival uses one egg.
  Containers and other blocks that take the use keep precedence, and
  Adventure and Spectator can't use eggs on blocks.
- **On water or lava** (`SpawnEggItem.use`, `Fluid.SOURCE_ONLY`): with no
  block or mob targeted, a source in reach gets the mob in its own cell.
- **On a spawner or trial spawner** (`Spawner.setEntityId`): the spawner
  makes that mob; a trial spawner resets its state data, spawns only that
  mob in both configurations (`overrideEntity` and `withSpawning`), keeps
  its ominous flag and goes inactive; the override is saved (`entity`).
  With `spawner_blocks_work` off the use fails ("Spawner blocks are not
  enabled").
- **On a mob of its own type** (`spawnOffspringFromSpawnEgg`, first among
  mob uses after name tags): a baby at the parent's feet, facing south.
  Breeding animals use the game's own breeding child (`animal_child` with
  the parent as both mates: variants, owner and colours carry over); other
  ageable mobs and the `setBaby` mobs get a bare entity without
  `finalizeSpawn`'s gear. Ageable babies start at age -24000. A mob that
  can't be a baby passes, and the egg then does nothing (it is not used on
  the block behind the mob).
- **Peaceful** (`EntityType.canSpawn`): a type not allowed in Peaceful
  fails, keeping the egg.
- **Dispensers** (`SpawnEggItemBehavior`, C2's table): the mob spawns in
  the cell in front, dropped onto the floor unless the dispenser faces
  up, the egg is used and `entity_place` is posted at the dispenser; on
  Peaceful a monster's egg stays in the dispenser. The pending spawn is a
  new saved dispenser output (code 5).

### Input paths

- **Mouse and keyboard**: everything above.
- **Controller** (`pad_menu.rs`): LB/RB page through Inventory, Crafting,
  then Java's item tabs in order and Saved Hotbars, each titled with Java's
  name; A, X and Y click, right-click and shift-click a cell through the
  same creative rules. On Saved Hotbars, Y loads the row under the cursor
  into the controller player's hotbar and X saves it. Search needs typing
  and stays with the keyboard.
- **CLI agent** (`agents.rs`, `agent/command.rs`): `catalog tabs` lists the
  shown tabs with their item counts; `catalog tab:<id> [query]` lists one
  tab's stacks in Java's order; a plain `catalog [query]` is unchanged.
  `hotbar save|load 1..9` saves or loads the agent's hotbar in creative.
  Spawn eggs need nothing new: `place` runs the shared use chain.
- **LAN guests**: the tabs, scrolling and search are the guest's local
  view, as the old palette's search was. A plain stack keeps its old slot
  code (its place in `Item::creative_palette`), so guests and hosts of
  earlier builds keep working; other stacks use 20000 + tab x 1000 +
  index, Destroy Item 405 and an empty cell 406. The host applies Java's
  creative click rules. A guest's hotbar shift-delete, middle-click clone
  and saved hotbars stay local-player features.

## Differences from Java

- Tabs, slots, scrollbar and panel are flat rectangles in the game's
  style, not Java's sprites. Tabs change on button press (Java waits for
  the release).
- Search matches every word of the query against the stack's name and
  enchantment lines; Java's search trees also match registry ids and
  tooltip lines, and `#` tag searches aren't supported.
- Stacks the game can't express: painting variants and goat horn
  instruments collapse to their single item; potions the game lacks are
  skipped with their registry gaps.
- The operator tab isn't shown (the game has no Operator Items Tab option;
  its blocks are registry gaps).
- The player preview draws the base skin layer without the outer layer,
  armour or held items, without lighting beyond a per-face shade, and it
  isn't clipped to its box.
- Spawn-egg mobs come from `Entities::spawn` (the game's own
  `finalizeSpawn` equivalent); custom names and entity data on the egg
  aren't modelled (the game's eggs carry no components). Babies of
  non-breeding ageable mobs are fresh entities rather than each class's
  `getBreedOffspring` (which for most is the same thing).
- Saved hotbars are a text file, not NBT, and LAN guests can't load them
  (they'd need a new packet); controllers have no search tab.
- The survival inventory's hotbar stays 2 pixels lower than Java's (every
  container screen's shared spacing, Track 2's), and its recipe toggle
  (Track 5's) still sits at the panel's top right, beside Java's
  "Crafting" label.

## Gaps left

- **Ender Dragon spawn egg**: not registered. The game's dragon exists
  only as the End fight's boss (`entity::dragon::Fight`); an egg-spawned
  dragon would need the dragon to run outside that fight. Its gap entry
  stays at v0.18 with that reason, and item 1937 is kept for it; moving it
  is the integrator's and owner's call.
- Nothing was seen: no screenshot, no play. The layout, tab art, preview
  and icons need Track 0's software screenshots and the owner's play.
- No frame-time run (the owner's, on the reference Mac). The creative
  screen and preview only add UI vertices while the inventory is open.
