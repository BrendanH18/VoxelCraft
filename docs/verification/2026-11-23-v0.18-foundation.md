## What was built

1. **Screenshots on Boat with a software GPU.** The game's `--screenshot`
   path renders on a Boat sandbox (x86_64, no GPU) through Mesa's software
   Vulkan driver (lavapipe, `mesa-vulkan-drivers` 25.2.8 on Ubuntu 24.04)
   under Xvfb. wgpu picks `llvmpipe (LLVM 20.1.2, 256 bits) (Vulkan)` with
   no code change: lavapipe has the storage buffers in vertex shaders the
   chunk renderer needs, enough texture-array layers and an sRGB swapchain
   format whose images can be copied back. `scripts/boat-capture.sh` wraps it:
   it runs through `scripts/boat-check.sh -- CMD`, so it shares the
   worktree's sandbox, slot, lock and warm `ci` build. It installs the
   packages the first time, builds the `ci` binary, starts one 3840 × 2160
   Xvfb screen and runs `tools/capture_scenes.py`. The PNGs come back as a
   base64 tar on the check's standard output and are unpacked into
   `target/captures/<commit>[-dirty]/`. Documented in
   [development: screenshots on Boat](../development.md#screenshots-on-boat).
2. **Capture harness gaps**, each a command-line flag:
   - `--gui-scale auto|N`: the GUI Scale for the run (scripted runs read no
     `options.txt`). It goes through the same `Settings.gui_scale` the options
     use, so `Ui::gui_scale` still caps it to the window.
   - `--open-recipe-book`: the recipe book open. It opens in the inventory,
     or beside a crafting table opened with `--open-block`.
   - `--creative-tab <id>`: the creative inventory, validated against
     Java's 14 tab ids. It implies `--creative` and `--open-inventory`.
     There are no tabs yet, so every id shows today's single palette. Track 4
     reads `args.creative_tab` in `Game::start` when it adds the tabs.
   - `--hardcore`: a world the run creates is Hardcore. With `--health 0`
     that is the Hardcore death (today: Spectator and a "Game over" popup;
     track 2 brings Java's screen).
   - `--gamerule name=value` (repeatable): any rule the game enforces, checked
     against the rule table when parsed. `advance_time=false` and
     `advance_weather=false` hold `--time` and `--weather` for a capture.
   - `--weather thunder`: a thunderstorm at full strength from the start
     (`Weather::set_thunder(now)`), beside `clear` and `rain`.
   - `--open-block` now opens a crafting table too. It already opened the
     other workstations and containers.
   - Resolution was already covered by `--size WxH`, and time by `--time`.
3. **Comparison scenes:** 31 named scenes in
   [`tools/capture_scenes.json`](../../tools/capture_scenes.json) (materials,
   mobs, ui, title and atmosphere groups; 76 captures with the UI and title
   resolution × GUI-scale variants), run by `tools/capture_scenes.py`.
   Material and mob scenes are built with `--place` high above the terrain,
   so they don't change with world generation. Each run writes a
   `manifest.json` with the commit, the renderer and each capture's settings
   and arguments. Documented in
   [development: comparison scenes](../development.md#comparison-scenes).
4. **[Art and UI guide](../art-and-ui.md):** pixel grid, colour pipeline,
   palette and contrast ranges, natural and manufactured patterns, glyph
   metrics, spacing, components and states, and progress icons. Values the
   typography, shared UI and material tracks may still tune are marked.

## Colour path

The surface is an `*Srgb` format and block, item and entity textures are
`Rgba8UnormSrgb`, so texture bytes show as authored. UI vertex colours are
linear floats, so the hardware encodes them for the sRGB target. The UI
constants were chosen as if they were sRGB, so they show lighter than
written (the guide's table gives each one). Sampled from the
`inventory-1280x720-guiauto` capture at `e8c2e536906f`: panel fill 229
(`#E5E5E5`, written 0.78), the "Inventory" title 137 (`#898989`, written
0.25) and the panel's bottom-right edge 155 (`#9B9B9B`, written 0.33). In the
before set at `f3b0c58`, the pause menu's buttons show 173 (written 0.42)
and Select World's disabled buttons 124 (written 0.2).
Each matches the sRGB encoding of the written value, so the path does
what the code says. The values were chosen as if no encoding happened. Java's
counterparts are 198, 64 and 85. The guide's decision is to write sRGB
values and convert them once. The typography track (1) owns the helper.

`mobs-uneven-ground` was at noon, where the zombie and skeleton burned

list changed between the two commits, not the game.

- `creative-search` and `creative-building-blocks` show the same single

## Gaps

- Software captures show appearance only. Nothing here measures
  performance, and no frame-time run was made (none is needed: no render
  or tick code changed).
- The two mob scenes differ between runs of one build, because mobs move
  during the 1.5-second wait. Every other scene is held: time and weather by
  game rules, and animation by `--animation-time`.
- Natural-terrain scenes (the atmosphere landscape, Nether and End) depend on
  world generation, so a generation change alters them. The material scenes
  are built and don't.
- The Java values in the guide still need the owning tracks' fixtures.
