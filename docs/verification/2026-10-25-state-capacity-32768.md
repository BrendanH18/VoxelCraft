# Block-state and texture capacity raise — 2026-10-25

[Roadmap](../roadmap.md#v012-scope-building-materials) · [Requirement inventory](../requirements.md) · [16,384 raise](2026-10-20-state-capacity.md) · [ID reservations](../architecture.md#v012-track-reservations)

Scope: v0.12 work item 0 (BLD-06), on `t3/v0-12-building-materials` after
`ec74556`. The owner approved the v0.12 decisions on 2026-10-25, including
raising `STATE_CAPACITY` to 32,768 before the content tracks start. The
[registry audit](2026-10-23-v0.12-registry-audit.md) puts v0.12 at 3,795
states at least and likely 6,000–8,000, against 4,643 free IDs.

Texture layers were a second limit. 1,775 of 2,048 layers were in use, and
v0.12's copper stages, candles, stone families, stripped logs and utilities
need more than the 273 that were left, so the texture capacity rose too.

## Change

- `world::block::STATE_CAPACITY` rises from 16,384 to 32,768. Block items
  still fit exactly: `BLOCK_ITEM_BASE` (0x8000) + 32,768 = 0x10000, and the
  compile-time assert in `item.rs` holds. This is the most the current
  block-item encoding allows.
- Chunk files take the oldest header that holds every state they store:
  `VXC2` below 4096, `VXC3` below 16,384, and the new `VXC4` otherwise. The
  records are unchanged. v0.9 to v0.11 builds refuse `VXC4` files and keep
  them as `chunks.bin.unknown-…` instead of overwriting them, as the
  16,384 raise arranged.
- The LAN `PROTOCOL` goes from 2 to 3. The handshake already compares game
  versions, so this only marks the change.
- The test-only registry entries move from 16,381–16,383 to 32,765–32,767.
- The `INFO` property table is built in a constant evaluation that now runs
  past rustc's default step budget, so it allows `long_running_const_eval`.
  The loop is bounded by `STATE_CAPACITY`. Building the library takes about
  6 s longer (32 s to 38 s on the M5, release profile), and the binary grows
  by 0.7 MB (12.9 to 13.7 MB).
- `tex::CAPACITY` rises from 2048 to 4096 texture layers, and `tex::ITEM_BASE`
  and the shaders' item-icon offset with it. Quads stay 12 bytes. Normal
  and cross quads take the 12th layer bit in word 1 bit 24. Detail quads
  (shaped blocks) take it in word 0 bit 30, the top bit of the lower v
  bound. That bound is at most 15 on a face with area, and the mesher now
  skips the edge faces of flat boxes, which have no area. Rail slope tags
  use the lower u bound, so they are unaffected.
- Paging: an adapter whose array limit is below `tex::COUNT` binds up to
  eight pages of the largest power-of-two size it supports
  (`tex::page_layers`), and the shaders take that page size as a
  specialized constant. Apple GPUs allow 2048 layers, so the M5 stays on
  one array until `tex::COUNT` passes 2048 and then binds two pages. An
  adapter with only wgpu's default 256-layer limit keeps eight 256-layer
  pages, which hold at most 2048 layers. Past that, such an adapter stops
  at startup with a message rather than drawing wrong textures.
- ID, item and texture ranges for each v0.12 track are reserved in the
  [architecture document](../architecture.md#v012-track-reservations).

## Checks

- `cargo fmt`, `cargo clippy --release --all-targets -- -D warnings` and
  `cargo test --release` pass (1,609 tests), as do the headless
  (`--no-default-features`) clippy and tests (1,417).
- New and updated cases:
  - Storage: a state at `STATE_CAPACITY - 1` round-trips through a `VXC4`
    file, a save whose highest state is 16,383 is written as `VXC3`, and
    state 32,768 is rejected as outside the registry.
  - Items: the block item of state 32,767 is item 0xFFFF and maps back.
  - Mesh: high layers 4095, 3072 and 2560 (bit 11 with bits 10 and 9) decode
    exactly for cube, detail (stairs) and cross quads, with geometry, light
    and AO unchanged from the same blocks at low layers.
  - `tex::page_layers` covers the full-array, Apple and 256-layer cases.
  - Every block shader parses and validates in the unpaged, 256-layer and
    2048-layer variants, and the page shift is substituted.
- Headless `--bench --rd 8`, alternating the pre-change build (`ec74556`)
  and the changed build five times each. Every difference is within
  run-to-run noise:

| Measure | Before (mean of 5) | After (mean of 5) |
|---|---|---|
| Gameplay light initialisation | 36.5 ms | 36.2 ms |
| Snapshot + mesh, 1 thread | 0.596 ms/chunk | 0.578 ms/chunk |
| Stream rd 8 on 9 workers | 0.57 s | 0.57 s |
| Palette pack (64 KiB lookup, was 32 KiB) | 12.5 µs/chunk | 12.7 µs/chunk (runs 10.3–14.5 overlap) |
| Byte pack | 9.0 µs/chunk | 8.8 µs/chunk |

  Generation (three alternating pairs) was 0.460–0.527 ms/chunk before and
  0.464–0.519 after.
- Rendering: the changed build drew a scripted scene (stairs, fence, wall,
  door, ladder, rail, scaffolding, honey, soul lantern, torch, poppy,
  sunflower, sea pickle and slab) correctly. A temporary build with paging
  forced to two 1024-layer pages (not kept) drew the same scene the same
  way, including blocks whose layers are on the second page, such as honey
  at layer 1771 and scaffolding at 1763. Pixel comparison between runs
  isn't possible, because streaming, water and clouds differ from run to
  run.

## Not yet checked

- The cost of paging on the M5 once `tex::COUNT` passes 2048. The offscreen
  `--bench-render` sweep (three alternating pairs, unpaged against forced
  1024-layer pages) varied more between runs, by 2.3–3.5 ms average frame
  time with different streamed content, than between modes. Measure it
  with the windowed scene suite when v0.12's textures push `tex::COUNT`
  past 2048, and pack the tracks' layers first.
- The windowed scene suite with the larger tables, which is still owed from
  the 16,384 raise (v0.20).
- Inventories, containers and automation entries that hold states from
  16,384 up are only partly protected in v0.9 to v0.11 builds. The chunk
  file is kept, but those builds drop items and entries they don't know
  when they save. Don't open a world that uses v0.12 blocks in an older
  build.
