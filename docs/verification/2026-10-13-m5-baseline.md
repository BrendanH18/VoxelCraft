# M5 scene baseline — 2026-10-13

> **Correction (2026-10-13 review).** This recording is **not a valid
> baseline** and must be re-measured with the fixed harness
> ([review fixes](2026-10-13-review-bench-fixes.md)). The raw data stays
> unchanged as a record. The original text claimed every streaming run completed
> 3,600 simulation ticks with zero discarded time; that was wrong. The defects are:
>
> - **Streaming run 3 is invalid.** It reports `completed_simulation_ticks: 0`
>   and `entities_end: 0` over 180 sampled seconds. The simulation was paused.
>   The old harness had no paused-time counter and did not check
>   ticks against sample time. Its zero discarded time hid the pause.
> - **11 of the 12 non-streaming runs did not render the scene during sampling.** Their
>   chunk-arena GPU figures read 0. The renderer resets those figures only when it
>   acquires a surface image, and arena pages are never released. A zero reading
>   at the end therefore means that every frame after the first chunk upload
>   skipped the surface (hidden or occluded window). Skipped frames sleep 8 ms.
>   That matches these runs' median frame times of 10.8–12.4 ms and their
>   clustering near 87 FPS. Those frame statistics measure the occluded-window
>   path, not rendering.
> - **Automation run 3 is anomalous.** It is the only non-streaming run with
>   non-zero arena figures, so it presented frames. It recorded 141.4 FPS, an 8.34 ms
>   median and 1,358 MiB peak RSS, compared with 86.7/96.8 FPS and 3,060/3,411 MiB in
>   the other automation runs. The three automation runs measured different
>   conditions and are not a range.
> - **The entity scene lost its population.** It ended at 148–150 mobs, compared
>   with the 160 fixture mobs plus natural spawns. The fixture's zombies and
>   skeletons burned in daylight.
> - The old harness also autosaved during samples. It could accept stray
>   keyboard or controller input. Its route cameras stayed at spawn height, it
>   hard-coded the present mode and it reported 0 rather than "unavailable" for
>   GPU memory.

The original summary follows, with the streaming results recomputed. None of
these figures may be used as an STR-01 baseline or for comparisons.

## Source and procedure

Measured commit: `94a34ddb0ceb011cee6f68c899c8654103182da6`, clean at build
and measurement start. Runtime source fingerprint:
`0b1d7f17a78c8d30c3fbfa4ce9b5da8c6a2b52b0d1cb71884409ffc851c814a7`.
The fingerprint omitted `packaging/icons/*`, which the executable embeds.
The summary records the executable SHA-256; all 15 reports match the source
stamp. The immutable measured binary remains in ignored local benchmark output.
Subsequent placement edits were prepared while this fixed binary ran; no builds
ran during measured scenes.

Hardware: Apple M5 MacBook Pro, 10 logical CPU cores, 10 GPU cores, 16 GiB RAM,
macOS 27.0.1, native display 3024 × 1964. Power/thermal telemetry was not recorded.
Requested configuration: 1920 × 1080 physical pixels, VSync disabled
(the harness assumed an uncapped mode rather than reading the resolved one),
enhanced graphics, seed 12345, 256-block view range (`--rd 8`) and a
128-block simulation distance. The old configuration flag was true for every
run, but it did not check sample validity. The specification and recorded
overrides describe camera flight and initial health.

Three independent runs per scene: ten seconds of warm-up, then 60 seconds for
survival/building/entities/automation and 180 seconds for streaming. The runner
starts fresh worlds sequentially.

```sh
CARGO_TARGET_DIR=/path/to/cache python3 tools/benchmark_scenes.py --repeats 3 --output target/benchmarks/m5-baseline
```

## Artifact verification and next work

All 15 compressed raw sample sets were re-read independently. Sample counts,
the reciprocal mean of the slowest rounded-up 1%, nearest-rank p99 and counts
above 50 ms reproduce the reported statistics. They describe the recorded
intervals; the defects above concern what those intervals measured. The
preserved executable's hash matches the summary. Raw statistics and
hardware/configuration metadata are tracked; compiled binaries and temporary
worlds remain outside version control.

Next: re-run the full suite with the fixed harness on an otherwise idle M5. The
window must stay visible and unobstructed. Accept only runs whose reports have
`run_valid: true` and a summary with `all_runs_valid: true`. Then profile
CPU/GPU submission, mesh upload and streaming/light work. Explain memory
variation, set hitch/queue budgets and optimize measured bottlenecks. Capture
native resolution and the wider encounter matrix before full acceptance.
